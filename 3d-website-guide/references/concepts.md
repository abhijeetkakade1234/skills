# Concept recipes: finding the signature transformation

The hero idea should be a **transformation only this product can show**, played by scroll.
Ask: what does the product turn into what? What does the customer see before vs after?
Then stage that change as one continuous 3D moment the visitor scrubs back and forth.

| Product type | Signature transformation | Proof moment |
|---|---|---|
| Computer vision / AI perception | "How you see it vs how the machine sees it": a solid world scanned into wireframe; only the objects that matter stay solid and get detection brackets | A tracked object crosses a line and a counter ticks +1 (causal) |
| Analytics / data | Raw scattered points (events) flow and settle into a clean chart | Hover a bar to see the events it came from |
| Payments / fintech | Coins/transactions stream in, sort, reconcile into a ledger that balances | A mismatch appears and resolves |
| Logistics / supply chain | Parcels route through a network of nodes in real time | Zoom from one parcel to the whole map |
| Developer tools | Code tokens compile into a running service, nodes light up | A request travels end to end with latency labels |
| Hardware / devices | Exploded view assembles into the product as you scroll | Each part labelled when it docks |
| Security | A surface scanned layer by layer, a threat isolated and sealed | Before/after attack path |
| Health / bio | Cells or molecules organise into a readable structure | One marker highlighted and explained |
| Consumer / lifestyle | The product in a small world that changes mood (time of day, season) | A material or colour swap the visitor controls |
| Agencies / portfolios | Each project as a room the camera visits | A cursor reveal shows the process under the result |

## Story beats template
1. **Hero**: the calm "before" world. Headline names the customer's reality.
2. **Signature transition**: the transformation, scrubbed by scroll, reversible.
3. **Proof**: the moment that makes it believable (a count, a match, a balance).
4. **How it works**: the camera travels through the system's stages (3-4 stations).
5. **Product**: capabilities + a framed product shot (sample data).
6. **Demo**: real footage/data if consented, else clearly labelled sample replay.
7. **Platform / roadmap**: honest (live product + unnamed "in development" slots).
8. **Contact**: a scale reveal (one unit -> many) behind the CTA.
9. **Footer**: a last scene (giant wordmark that reacts to the cursor).

## Style choice
| Style | Looks | Build cost | Risk |
|---|---|---|---|
| Matte clay + wire/points | Premium, calm, technical | Low (simple geometry reads as deliberate) | Can feel cold; needs good lighting/AO |
| Stylised colour | Friendly, playful | Medium | Taste: easily looks toy-like |
| Photoreal | Impressive | High (models, textures, lighting) | Uncanny / "old video game" if under-done |
| Pure abstract (particles, lines) | Futuristic | Low-medium | Becomes "AI slop" if it means nothing |

Pick the one the team can execute at 90% quality, not the one that sounds best.
